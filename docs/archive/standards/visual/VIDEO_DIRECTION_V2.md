# 문장군 리뷰 영상 기획 및 편집 표준 v2

> 기준 영상: `output/inbox_20260609/010_구축소음_20260609_095709/010_구축소음_직원편집.mp4`  
> 목적: 직원 편집본의 릴스 감각을 자동 영상 엔진의 표준 DNA로 이식한다.

## 결론

v1 방향인 `6섹션 = 6장면` 구조는 자동화 가능성 검증에는 유효했지만, 인스타그램 릴스용으로는 컷 밀도와 자막 리듬이 부족하다.

v2 표준은 아래 구조를 따른다.

```text
script.md / SRT / voice.mp3
↓
영상용 micro-beat timeline 재해석
↓
15~25개 컷
↓
사진 역할별 자동 매칭
↓
짧고 큰 타이포 + 리듬감 있는 전환
↓
실제 리뷰캡처로 증명
```

즉, 영상 자동화의 핵심은 "SRT 6줄에 사진 6장을 붙이는 것"이 아니라, 리뷰 사연을 숏폼 편집 비트로 다시 쪼개는 것이다.

## 직원 편집본에서 확인한 핵심 DNA

### 1. 고정 브랜드 배지는 쓰지 않는다

좌상단 고정 텍스트, 상단 브랜드 라벨, 카드형 설명 헤더는 AI 슬라이드처럼 보인다. 직원 편집본은 브랜드 배지를 앞세우지 않고 사진과 자막만으로 흐름을 만든다.

원칙:

- 상단 고정 배지 금지
- 브랜드 노출은 마지막 리뷰 증명 또는 아주 작은 워터마크 수준
- 화면의 주인공은 브랜드가 아니라 고객의 불편과 해결감

### 2. 컷 수는 많아야 한다

직원 편집본은 약 32.6초 동안 1초 안팎의 빠른 컷과 반복 컷을 사용한다. 자동 영상도 30~35초 기준 최소 15컷, 권장 18~24컷을 목표로 한다.

원칙:

- `HOOK`은 2~4컷
- `SCENE/CONFLICT`는 현장 동선 컷을 여러 장 사용
- `SOLUTION`은 실측 컷 2~3개 + 제품 썸네일 1개
- `TWIST`는 완료 사진 4개 이상 사용
- `CLOSE`는 리뷰캡처 + 핵심 리뷰 문구 확대

### 3. 자막은 짧고 커야 한다

직원 편집본의 자막은 내레이션 전문이 아니라 키워드형 문구다.

기본 폰트:

- 모든 자막/UI 텍스트: `nelnasamchae.ttf`
- 이후 HTML/Hyperframe 프리뷰와 최종 영상 렌더러는 이 폰트를 기본값으로 사용한다.

좋은 문법:

```text
구축 빌라
현관 소음 지옥

드디어 해방!

벽 얇은 구축 빌라
현관 소음은 일상

밤낮없이 들리는
이웃집 소리

냄새까지 유입

소음, 냄새 완벽 차단!
정말정말 좋습니다 ㅠㅠ
```

원칙:

- 한 화면 자막은 1~2줄 중심
- 문장보다 명사구/감정어/결과어 우선
- 중앙 또는 중앙 하단에 크게 배치
- 강조 색은 노란색 계열을 기본으로 하되, 과한 형광색은 피한다
- 자막은 나레이션의 "문장"이 아니라 "비트"와 맞춘다

### 4. 이미지에 계속 어두운 블러를 넣지 않는다

현장 사진은 증거 자료다. 계속 어둡게 덮으면 현장감이 죽는다.

원칙:

- 문제 장면에서만 짧게 어둡게 누른다
- 외관/계단/실측/완료 사진은 가능한 선명하게 보여준다
- 배경 블러는 리뷰캡처 카드나 제품 썸네일 합성처럼 필요할 때만 사용한다

### 5. 사진은 공간 동선으로 배열한다

직원 편집본은 외관 → 입구계단 → 계단실 → 현관 → 실측 → 제품 → 완료 순서로 공간을 이동한다. 이 순서가 현장감을 만든다.

표준 순서:

```text
문제명명
→ 시공전/비포
→ 시공완료/애프터 짧은 선공개
→ 현장 외관
→ 입구/계단/복도
→ 문제 체감
→ 실측 근거
→ 제품 선택
→ 완료 결과
→ 리뷰 증명
```

### 6. 제품 썸네일은 "제품선택" 순간에 짧게 넣는다

`모던 디자인`, `3연동중문`, `고시`, `투명강화유리`처럼 제품 관련 내레이션이나 자막이 나오면 `상품썸네일.jpg`가 0.7~1.3초 등장해야 자연스럽다.

원칙:

- 제품 썸네일은 길게 보여주지 않는다
- 현장 이미지 위에 카드처럼 얹거나, 짧은 플래시 전환으로 삽입한다
- 광고처럼 뜨지 않게 앞뒤 문구를 고객 선택 맥락으로 연결한다

예:

```text
고객이 선택한
모던 3연동중문
```

### 7. 싱크는 SRT 기준이 아니라 micro-beat 기준이다

현재 SRT는 6개 구간이므로 영상 컷과 자막 싱크를 맞추기에 너무 거칠다. 영상 엔진은 SRT를 그대로 쓰지 않고, 각 SRT/내레이션 구간을 2~5개의 micro-beat로 재분해해야 한다.

예:

```text
SRT:
밤낮없이 들리는 이웃집 소리, 냄새까지 유입

영상 비트:
1. 밤낮없이 들리는
2. 이웃집 소리
3. 냄새까지 유입
```

## 자동화 엔진 설계 판단

### 최선의 방향

현 시점의 최선은 `Hyperframe/HTML 기반 micro-beat renderer`다.

이유:

- 직원 편집본은 사진, 텍스트, 빛 효과, 카드, 제품컷, 리뷰캡처가 빠르게 겹치는 구조다.
- 이런 레이어/애니메이션 구성은 MoviePy보다 HTML/CSS/JS가 조정하기 쉽다.
- Remotion도 가능하지만, 이 프로젝트는 이미 HTML 기반 사고방식과 잘 맞는다.
- FFmpeg는 최종 인코딩과 오디오 믹싱 역할로 두는 것이 맞다.

### 엔진 구성

```text
1. 리뷰 패키지
   script.md / subtitle.srt / voice.mp3 / 이미지 폴더

2. 사진 역할 태깅
   before, after, place, entry, stairs, measurement, product, review_capture

3. micro-beat 생성
   6개 SRT를 15~25개 편집 비트로 재분해

4. edit_recipe.json 생성
   시간, 이미지, 자막, 모션, 효과음, 강조 단어 기록

5. HTML/Hyperframe 렌더
   레이어, 자막, 이미지 전환, 키워드 모션 구현

6. FFmpeg
   narration + BGM + SFX 믹싱, 최종 MP4 출력
```

## v2에서 금지할 것

- SRT 6줄 = 장면 6개로 직접 렌더링
- 좌상단 고정 브랜드 배지
- 전 구간 어두운 블러/딤 처리
- 작은 하단 설명 자막만 사용하는 방식
- 나레이션 한 문장을 한 화면에 길게 표시
- 제품 썸네일을 무맥락으로 삽입
- 리뷰캡처를 너무 작게 또는 너무 늦게만 보여주는 방식
