# STORY_EXTRACTION_RULES.md — 리뷰 → 사연극 재료 추출 규칙

> 마지막 업데이트: 2026-06-08
> 목적: 리뷰 원문에서 사연극의 재료(사건·갈등·반전·훅)를 추출하는 규칙을 정의한다.
> 이 문서가 먼저이고, `prompts/screenplay.txt`는 이 규칙을 기반으로 설계된다.

---

## 1. 왜 이 문서가 필요한가

리뷰마다 사건의 형태가 다르다. 같은 6단계 구조(HOOK~CLOSE)에 넣더라도,
**사건을 어떻게 뽑아내는가**에 따라 결과물이 완전히 달라진다.

```
리뷰 원문
  ↓ [이 문서의 규칙]
사건 · 갈등 · 반전 · 훅 (재료)
  ↓ [screenplay.txt]
사연극 6단계 스크립트
```

---

## 2. 추출 프로세스 (5단계)

### STEP 1 — 사건 시퀀스 추출

리뷰에서 **시간 순서로 일어난 일**을 뽑는다.
"만족합니다", "추천합니다" 같은 평가 문장은 무시하고,
**동사가 있는 사건 문장**만 추출한다.

**추출 기준:**
- ✅ 동사가 있는 사건 → "택배를 챙기다가 고양이가 나갔다"
- ✅ 상태 변화 → "나무 문짝 아래가 다 들뜨고 있어서"
- ✅ 행동 → "힘줘서 팍팍 닫던 문"
- ❌ 평가 → "너무 만족합니다" (버린다)
- ❌ 일반 설명 → "문장군 리뷰가 좋은 것 같아서" (버린다)

**예시 — 리뷰11 (경첩삭음):**
```
사건 시퀀스:
1. 엄청 오래된 구택, 나무문틀이 많이 틀어짐
2. 기존 문 경첩 나사가 다 삭아서 드릴이 헛돌음
3. 힘줘서 팍팍 닫아야 문이 닫힘
4. 문 4개 교체
5. 힘 안 줘도 슥슥 열리고 닫힘
6. 집안 분위기가 깔끔해짐
7. "더 바꿀 문이 없다는 게 아쉬울 정도"
```

---

### STEP 2 — 갈등 핵심 추출

사건 시퀀스에서 **가장 불편하거나 고통스러운 지점 1개**를 고른다.
이것이 [CONFLICT] 섹션의 핵심이 된다.

**갈등 유형 분류:**

| 유형 | 설명 | 대표 예시 |
|------|------|----------|
| 🔴 **물리적 고통** | 몸으로 겪는 불편 | 문 안 닫힘, 문짝 들뜸, 소음 |
| 🟠 **감정적 고통** | 스트레스, 분노, 불안 | 인테리어 멘탈 붕괴, 고양이 탈출 공포 |
| 🟡 **누적 고통** | 오래 참아온 것 | 몇 년째 힘줘서 닫는 문, 구축 방치 |
| 🟢 **관계 갈등** | 가족 간 의견 충돌 | 부모님 반대, 배우자 설득 |

**규칙:**
- 갈등은 **1개만** 고른다 (2개 이상이면 더 구체적인 것 선택)
- "불편했다"가 아니라 **체감 가능한 장면**으로 뽑는다
  - ❌ "불편했어요" → 추상적
  - ✅ "힘줘서 팍팍 닫아야 문이 닫혔다" → 체감 가능

**예시:**
| 리뷰 | 갈등 핵심 | 유형 |
|------|----------|------|
| 2 | 택배 챙기다 고양이가 나가서 옆집 사람이 알려줌 | 🟠 감정 |
| 5 | 아이 씻기면 나무 문짝에 물 뿌려놔서 아래가 다 들뜸 | 🟡 누적 |
| 8 | 이사+인테리어로 멘탈 피폐, 원하던 디자인이 안 맞음 | 🟠 감정 |
| 11 | 경첩 나사가 삭아 드릴이 헛돌 정도, 매번 힘줘서 닫음 | 🔴 물리 + 🟡 누적 |

---

### STEP 3 — 반전 포인트 추출

사연극의 하이라이트. **예상 밖의 결과 또는 감정 전환**을 찾는다.
[TWIST] 섹션의 핵심이 된다.

**반전 유형 분류:**

| 유형 | 설명 | 대표 예시 |
|------|------|----------|
| 💬 **제3자 반응** | 본인 아닌 다른 사람의 반응 | 정수기 기사가 물어봄, 부모님 칭찬일색 |
| 😂 **감정 과잉** | 예상보다 과한 만족 감정 | "더 바꿀 문이 없어서 아쉽다", "힐링이었다" |
| 🔄 **역전** | 기대 vs 현실이 뒤집힘 | 디자인 못 맞출 줄 → 더 깔끔하게 나옴 |
| 🎯 **한 줄 펀치** | 리뷰어 본인의 킬링 한 마디 | "중문없이 어찌 살았나 싶을 정도" |

**규칙:**
- 반전은 **리뷰 원문에서 직접 발견**해야 한다 (AI가 만들지 않는다)
- 리뷰어의 말투를 최대한 살린다
- 반전이 약하면 사연극보다 다른 콘텐츠 타입이 맞을 수 있다

**예시:**
| 리뷰 | 반전 포인트 | 유형 |
|------|-----------|------|
| 2 | 정수기 기사가 중문 좋다며 물어봄 → 문장군 홍보해드림 | 💬 제3자 |
| 5 | "속이 다 시원해요" — 아이 물놀이 스트레스에서 해방 | 😂 감정과잉 |
| 8 | "인테리어로 피폐해진 멘탈에 힐링이었습니다" | 🔄 역전 |
| 11 | "더 바꿀 방문이 없다는 게 아쉬울 정도 ㅋㅋㅋ" | 🎯 한줄펀치 |

---

### STEP 4 — HOOK 프레이밍

**가장 중요한 단계.** 같은 사건이라도 프레이밍에 따라 조회수가 10배 차이난다.

**HOOK 공식:**
```
[타겟 공감] + [사건 미리보기] + [결말 궁금증]
```

**HOOK 유형별 패턴:**

| 유형 | 패턴 | 예시 |
|------|------|------|
| **공포/긴박** | "~할 뻔한 사연" | "택배 가지러 나갔다가 고양이를 잃어버릴 뻔한 집사님" |
| **공감/일상** | "~하는 집은 공감" | "아이 씻기면 화장실 문이 부풀어오르는 집" |
| **고통 체감** | "~년째 ~하는 사람" | "힘줘서 팍팍 닫던 방문이 어느 날 갑자기 사라졌습니다" |
| **감정 반전** | "~했는데 결국~" | "인테리어 공사에 멘탈 다 나갔는데, 이건 힐링이었대요" |

**HOOK 작성 규칙:**
1. **상품명(중문, 도어) 금지** — 사건이 먼저, 제품은 나중에
2. **타겟 호칭 사용** — "집사님", "아이 키우는 집", "구축 사시는 분"
3. **15자 이내** — 자막으로 뜰 때 한 줄에 들어와야 함
4. **물음/호기심 유발** — "~한 사연", "~한 집", "~할 뻔한"

**❌ 나쁜 HOOK:**
```
"문장군 중문 설치 후기"  → 광고
"중문 설치 만족 리뷰"   → 제품 중심
"문장군에서 시공받았어요" → 사건 없음
```

**✅ 좋은 HOOK:**
```
"택배 가지러 나갔다가 고양이를 잃어버릴 뻔한 집사님"
"힘줘서 팍팍 닫던 방문이 어느 날 갑자기 사라졌습니다"
"인테리어 공사에 멘탈 다 나갔는데, 이건 힐링이었대요"
"아이 씻기면 화장실 문이 부풀어오르는 집"
```

---

### STEP 5 — 원문 킬링 문장 추출

[CLOSE] 섹션에 들어갈 **리뷰 원문 그대로의 문장**을 뽑는다.
이 문장은 AI가 다듬지 않는다. 리뷰어의 맞춤법, 말투, 이모티콘 그대로 사용.

**선택 기준:**
- 감정이 가장 잘 드러나는 1~2문장
- "~해서 좋았어요" 같은 평범한 문장은 피한다
- 리뷰어만의 독특한 표현이 있으면 최우선

**예시:**
| 리뷰 | 킬링 문장 (원문 그대로) |
|------|----------------------|
| 2 | "중문없이 어찌 살았나 싶을정도로" |
| 5 | "아주 깔끔해져서 속이 다 시원해요 ㅎㅎ" |
| 8 | "피폐해진 멘탈에 문장군의 상담부터 실측, 시공까지의 과정은 너무도 매끄러워서 힐링이었습니다" |
| 11 | "더 바꿀 방문이 없다는게 아쉬울 정도? ㅋㅋㅋ" |

## 4. 사연극 부적합 판별 기준

모든 리뷰가 사연극에 적합한 건 아니다. 아래에 해당하면 **다른 콘텐츠 타입**을 고려한다.

| 부적합 신호 | 적합한 대체 타입 |
|------------|----------------|
| 사건 시퀀스가 2개 이하 (일어난 일이 없음) | FAQ형 |
| 갈등이 없음 (처음부터 만족) | 사회적증거형 |
| 반전이 없음 (순탄한 진행) | FAQ형 또는 사회적증거형 |
| 시공자/기사 캐릭터가 주인공 | 현장다큐형 |
| "할까 말까" 의사결정 과정이 핵심 | 고민상담형 |

**예시 — 리뷰7 (장인정신) → A-급인 이유:**
- 사건 시퀀스: 있음 (시공 과정 묘사)
- 갈등: **약함** (걱정했으나 기우였다)
- 반전: 없음 (처음부터 끝까지 만족)
- → 사연극보다 **현장다큐형**이 적합

## 5. screenplay.txt로의 연결

이 문서의 5단계 추출 결과는 `screenplay.txt` 프롬프트에서 다음과 같이 매핑된다:

```
STEP 4 HOOK 프레이밍    → [HOOK] 섹션
STEP 1 사건 시퀀스 앞부분 → [SCENE] 섹션
STEP 2 갈등 핵심        → [CONFLICT] 섹션
(시공/해결)             → [SOLUTION] 섹션
STEP 3 반전 포인트      → [TWIST] 섹션
STEP 5 킬링 문장        → [CLOSE] 섹션
```

> ⚠️ 이 매핑은 `screenplay.txt`에서 구체적인 프롬프트로 구현된다.
> 이 문서는 **규칙**이고, `screenplay.txt`는 **실행 프롬프트**이다.

---

## 6. 추출 품질 체크리스트

screenplay.txt에 넘기기 전, 추출 결과를 자체 검증한다:

- [ ] 사건 시퀀스가 3개 이상인가?
- [ ] 갈등이 **체감 가능한 장면**으로 뽑혔는가? ("불편했다"가 아닌 구체적 행동/상태)
- [ ] 반전이 **리뷰 원문에서 직접 발견**되었는가? (AI 창작 아닌가?)
- [ ] HOOK에 상품명(중문, 도어, 문장군)이 없는가?
- [ ] HOOK이 15자 이내인가?
- [ ] 킬링 문장이 리뷰 원문 **그대로**인가?
- [ ] 사연극 부적합 신호에 해당하지 않는가?
