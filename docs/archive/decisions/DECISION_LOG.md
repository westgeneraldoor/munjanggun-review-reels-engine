## [D-015] SRT/TTS 입력 계약과 TTS 품질 기준
- **날짜:** 2026-06-08
- **결정:**
  1. SRT는 `script.md`의 자막 텍스트 기준으로 생성한다.
  2. TTS는 `script.md`의 내레이션 기준으로 생성한다.
  3. 실제 TTS 입력(`tts_text`)은 발음/띄어쓰기 수준에서 자연스럽게 정규화할 수 있다.
  4. TTS는 Gemini 최신 공식 TTS를 우선 사용하되, 품질 기준 미달 시 DECISION_LOG 승인 후 교체 검토 가능하다.
  5. 현재 구현 모델은 `gemini-3.1-flash-tts-preview`이다. Stable 모델이 제공되면 교체 가능하다.
- **추가 결정:** 시간에 맞추기 위해 내레이션을 요약하거나 삭제하지 않는다. 길이는 말 속도/오디오 속도 조정으로 맞춘다.
- **사유:** 화면 자막은 짧아야 하고, 음성은 더 자연스럽고 풍부할 수 있다. 사연극 콘텐츠에서는 "좋은 글"만큼 "좋은 목소리"가 중요하다.
- **TTS 성공 기준:** 단골 카페 언니가 친구에게 실제 리뷰를 들려주는 느낌. 광고, 홈쇼핑, 뉴스, ARS, 유튜브 AI 낭독 톤은 실패.
- **영향:** F-002는 자막 텍스트 파싱 중심, F-003은 내레이션 추출 + TTS 정규화 + persona.txt 적용 중심으로 구현한다.
- **상태:** 🔒 LOCKED
- **재검토 조건:** Gemini TTS 실제 음성 품질이 CapCut 업로드 기준 미달일 때

## [D-017] TTS 레퍼런스 속도 고정
- **날짜:** 2026-06-08
- **결정:** 리뷰2 `택배 가지러 나갔다가 고양이를 잃어버릴 뻔한 집사님` 음원을 TTS 속도 레퍼런스로 고정한다.
- **기준:** 레퍼런스 음원은 전체 내레이션 공백 제외 244자, 음성 35.02초, 초당 약 6.97자.
- **글자수 원칙:** 신규 script.md 내레이션 글자수는 품질을 우선한다. 필요하면 조금 길어지거나 짧아져도 되며, 글자수만으로 실패 처리하지 않는다.
- **사유:** 사장님 확인 결과 이 음원 속도가 인스타 릴스 템포에 가장 적합했다. 단, 내용 품질이 핵심이므로 글자수 단속은 품질을 떨어뜨릴 수 있다.
- **영향:** generate.py는 TTS 내용을 자르거나 요약하지 않고, 공백 제외 글자수와 레퍼런스 속도(초당 약 6.97자)를 기준으로 목표 음원 길이를 계산해 말속도를 조정한다.
- **상태:** 🔒 LOCKED
- **재검토 조건:** 실제 업로드 테스트에서 말이 씹히거나 너무 느리다는 피드백이 반복될 때

## [D-018] 리뷰 원본 장기 관리 규칙

- **결정:** 리뷰 원본은 1개 리뷰당 1개 `.txt` 파일로 관리한다. 권장 파일명은 `001_짧은라벨.txt` 형식이다.

- **사유:** 리뷰번호는 스마트스토어 대시보드에서 리뷰 등록 사진을 찾는 키이고, 상품주문번호는 AppSheet에서 고객/실측/시공완료 사진을 매칭하는 키다. 100개 리뷰를 한 파일에 모으면 산출물 추적, 재생성, 실패 관리가 어려워진다.
- **영향:** generate.py는 구조화된 리뷰 파일을 파싱하고, script.md front matter에 `review_number`, `product_order_number`, `source_file`, `review_sequence`를 자동 포함한다. output 폴더와 파일명은 `001_짧은라벨_파일타입.확장자` 형식을 우선 사용한다.
- **상태:** 🔒 LOCKED
- **재검토 조건:** 리뷰 수가 수천 개 이상이 되어 파일 탐색 성능이나 운영 검색성이 떨어질 때

## [D-020] 생활 체감형 영상의 생성 B-roll 사용 원칙
- **날짜:** 2026-06-11
- **결정:** 실제 현장 사진만으로 음성의 핵심 의미를 증명하기 어려운 생활 체감형 리뷰에는 생성 이미지를 짧은 B-roll로 사용할 수 있다.
- **적용 예:** 020_로봇청소구축리모델링에서 `로봇청소기가 문턱에서 막힘`, `문턱 없이 통과함` 장면을 생성 이미지로 보강했다.
- **원칙:**
  1. 생성 이미지는 실제 시공 증거가 아니라 이해 보조 컷이다.
  2. 실제 증명은 현장 사진과 리뷰 캡처가 담당한다.
  3. 생성 컷은 0.8~1.5초 내외의 인서트로만 사용한다.
  4. 생성 컷은 나레이션의 구체 문장을 문자 그대로 만족해야 한다.
  5. `문턱 없이`라고 말하면 화면에 문턱, 턱, 레일, 단차, lip, raised strip이 없어야 한다.
  6. 생성 컷이 너무 광고/스튜디오처럼 보이면 현장 사진과 이질감이 커지므로 폐기하거나 짧게만 사용한다.
- **사유:** 020 실험에서 실제 현장 사진만으로는 로봇청소기 동선과 문턱 문제를 충분히 증명하기 어려웠다. 반면 무분별한 그래픽 박스/칩/라인 오버레이는 사진과 자막을 가리고 품질을 떨어뜨렸다.
- **영향:**
  - v2 이후에는 `claim -> real-photo proof 가능 여부 -> generated B-roll 필요 여부 -> literal visual QA` 단계를 추가한다.
  - 생성 이미지를 사용할 때는 사용 사실과 역할을 문서/레시피에 남긴다.
  - 떠다니는 설명 컴포넌트보다 장면 자체를 맞추는 방식을 우선한다.
- **상태:** 🔒 LOCKED
- **재검토 조건:** 실제 업로드/광고 성과에서 생성 B-roll이 신뢰도를 해친다는 피드백이 반복될 때

## [D-028] TTS 압축률/목소리 품질 하드 게이트
- **날짜:** 2026-06-12
- **결정:** 릴스 음성은 최종 길이와 초당 글자수만으로 통과 처리하지 않는다. 원본 TTS 길이와 최종 voice.mp3 길이를 모두 기록하고, `원본 TTS 길이 / 최종 음성 길이` 압축률을 검수한다.
- **기준:**
  - 권장 압축률: `1.00~1.12`
  - 주의 압축률: `1.13~1.18`
  - 실패 압축률: `1.20 이상`
  - `1.25 이상`은 발음 뭉개짐 위험이 높으므로 렌더 금지
- **추가 기준:** 기존 승인 톤과 다른 목소리, 지나치게 차분한 낭독, 낮고 처지는 톤, 받침/조사가 뭉개지는 발음은 수치가 통과해도 실패다.
- **사유:** 025 living_review_v2에서 원본 TTS 약 `39.49초`를 최종 `28.94초`로 압축해 약 `1.36배`가 되었고, 사용자가 기존 문장군 음성과 다른 차분한 톤과 뭉개진 발음을 지적했다. D-024 초당 글자수만으로는 이 문제를 잡지 못했다.
- **영향:** `docs/review_video_publish_workflow_v2.md`, `docs/render_qa_rules_v2.md`, `CONTENT_QUALITY_STANDARD.md`, `docs/archive/handoffs/_context.md`에 음성 원본 길이/압축률/톤 품질 검수 기준을 추가한다.

## [D-029] 부족/부적합 사진의 생성 인서트 사용 게이트
- **날짜:** 2026-06-12
- **결정:** 릴스 제작 중 현장 사진이 부족하거나, 음성/자막의 핵심 의미를 보여주기에 부적합하면 이미지 생성 인서트를 제안할 수 있다. 단, 생성 이미지는 실제 시공 증거가 아니라 이해 보조용 인서트로만 사용한다.
- **사용 가능 조건:**
  1. 실제 사진만으로 해당 문장을 시각적으로 설명하기 어렵다.
  2. 장면이 시공 결과물/제품 디테일 증명이 아니라 생활상황, 불편 체감, 전후 맥락 보조에 해당한다.
  3. 생성 장면의 역할을 planning/edit recipe에 명시한다.
  4. 사용자에게 생성 인서트 사용 여부를 먼저 보고한다.
- **금지 조건:**
  1. 실제 시공 결과물, 제품 마감, 유리 색상, 레일/댐퍼 디테일을 생성 이미지로 대체.
  2. 고객 집을 실제처럼 속이는 증거 컷으로 사용.
  3. 리뷰에 없는 효과를 생성 이미지로 과장.
  4. 생성 이미지가 문맥과 문자 그대로 맞지 않는데 사용.
- **검수 기준:** 생성 컷은 나레이션 문장을 문자 그대로 만족해야 한다. 예를 들어 `문턱 없이 통과`라면 화면에 문턱, 턱, 레일, 단차, raised strip이 없어야 한다.
- **영향:** `docs/review_video_publish_workflow_v2.md`, `CONTENT_QUALITY_STANDARD.md`, `docs/archive/handoffs/_context.md`에 사진 부적합 시 생성 인서트 판단 절차를 추가한다.
- **상태:** 🔒 LOCKED
- **재검토 조건:** 실제 업로드 성과에서 생성 인서트가 신뢰도를 낮춘다는 피드백이 반복될 때
