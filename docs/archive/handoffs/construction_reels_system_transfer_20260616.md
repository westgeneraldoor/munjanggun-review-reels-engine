## 0. 먼저 결론

시공릴스 총괄은 바로 코딩, 렌더링, 폴더 구조 만들기부터 들어가면 안 된다.

리뷰릴스 프로젝트가 안정화된 이유는 HTML/MP4를 빨리 만들었기 때문이 아니라, 아래 순서가 생겼기 때문이다.

```text
상태판
-> 역할 분담
-> 후보/소스 검수
-> 작가 브리프
-> PD 기획안
-> 사용자 승인
-> HTML 프리뷰
-> QA
-> MP4 렌더
-> 문서 갱신
-> 다음 후보 준비
```

시공릴스도 같은 철학을 가져가야 한다. 단, 리뷰릴스가 `고객 리뷰에서 사건을 찾는 시스템`이라면, 시공릴스는 `촬영 소스에서 현장 드라마를 찾는 시스템`이어야 한다.

## 1. 리뷰릴스 시스템이 해결한 문제

초기에는 자동화 욕심 때문에 아래 문제가 반복됐다.

```text
1. 번호만 주면 바로 HTML까지 만들어버림
2. 음성보다 화면/자막이 먼저 가거나 늦게 따라옴
3. 훅이 추상적이라 첫 2초가 약함
4. 사진과 내레이션이 서로 다른 말을 함
5. 효과를 많이 넣다가 조잡해짐
6. 렌더 결과가 HTML과 다르게 보임
7. 신규 세션이 이전 결정을 모르고 같은 실수를 반복함
8. 완료 후 다음 후보/폴더 준비가 끊김
```

그래서 리뷰릴스 시스템은 자동화를 먼저 만든 것이 아니라, 실수를 막는 운영 체계를 먼저 만들었다.

시공릴스 총괄은 이 지점을 반드시 이해해야 한다.

## 3. 리뷰릴스 전체 A-Z 프로세스

리뷰릴스는 아래처럼 운영된다.

```text
1. 후보 리뷰를 고른다.
2. output 패키지 폴더를 만든다.
3. 사용자가 사진을 넣는다.
4. 사진을 직접 검수한다.
5. 사진 역할을 매핑한다.
6. 부족 컷을 판단한다.
7. 작가가 writer brief를 만든다.
8. PD가 목적/훅/타임라인을 정한다.
9. 사용자에게 기획 승인을 받는다.
10. 승인 후 script/SRT/TTS/HTML을 만든다.
11. HTML을 사용자가 본다.
12. 피드백을 반영한다.
13. HTML 승인 후 MP4를 렌더한다.
14. 렌더 결과를 다시 검수한다.
15. 캡션/해시태그를 점검한다.
16. 완료 문서를 정리한다.
17. 다음 후보와 사진 폴더를 준비한다.
```

중요한 것은 10번 이전에 이미 영상의 승부가 거의 난다는 점이다.

리뷰릴스 총괄이 배운 핵심:

```text
HTML을 빨리 만드는 팀보다,
HTML 만들기 전에 틀린 방향을 막는 팀이 더 잘 만든다.
```

## 5. 시공릴스 스타일은 아직 확정하면 안 된다

현재 시공릴스는 스타일 구상 전이다.

따라서 총괄은 바로 `이 스타일로 만들겠습니다`라고 확정하지 말고, 최소 3가지 방향을 제안해야 한다.

### 5.1 현장 다큐형

구조:

```text
현장 도착
-> 시공 전 상태
-> 실측/준비
-> 시공 중
-> 마감 디테일
-> 시공 후
```

장점:

- 시공팀이 찍은 영상의 장점을 가장 잘 살림
- 현장감과 신뢰감이 좋음

주의:

- 너무 길어지면 작업 기록 영상처럼 보임

### 5.2 장인 디테일형

구조:

```text
어려운 현장 조건
-> 기준선/실측
-> 보강/철거/마감
-> 디테일 확대
-> 완성
```

장점:

- 문장군 전문성 어필에 강함
- 가격 비교/저가 업체와 차별화하기 좋음

주의:

- 일반 시청자가 너무 기술적으로 느끼지 않게 해야 함

### 5.3 Before/After 임팩트형

구조:

```text
시공 전 1초
-> 시공 후 반전
-> 왜 달라졌는지 과정 압축
-> 마감/디테일
```

장점:

- 인스타 첫 2초 후킹이 강함

주의:

- 모든 케이스에 맞지 않음
- 전후가 명확한 사진/영상이 있어야 함

## 6. 시공릴스 팀 구조

리뷰릴스 팀 구조를 시공릴스에 맞게 변환한다.

| 역할 | 리뷰릴스 | 시공릴스 |
|---|---|---|
| 총괄 PD | 리뷰의 사건성과 인스타 전략 판단 | 현장 소스의 드라마와 브랜드 신뢰 판단 |
| 작가 | 리뷰 원문을 각색 | 촬영 소스에서 현장 스토리 추출 |
| 사진 큐레이터 | 리뷰 사진 역할 매핑 | 영상/사진 역할 매핑, 개인정보 위험 체크 |
| 편집 설계자 | 리뷰 beat 설계 | 시공 과정 beat 설계 |
| QA 감시자 | 싱크/과장/자막 검수 | 싱크/개인정보/회전/전후 의미 검수 |

시공릴스 작가의 공식 이름은 아래를 추천한다.

```text
현장 편집 작가
```

## 11. 리뷰릴스 총괄의 최종 조언

시공릴스는 가능성이 크다.

리뷰릴스가 고객의 말로 신뢰를 만든다면, 시공릴스는 현장 증거로 신뢰를 만든다.

하지만 시공릴스는 자료가 많을수록 더 위험하다. 영상과 사진이 많으면 `다 넣고 싶은 욕심`이 생기고, 그 순간 릴스가 아니라 현장 기록물이 된다.

시공릴스 총괄은 항상 아래 질문으로 시작해야 한다.

```text
이 케이스의 첫 2초에서 무엇을 보여주면 멈춰볼까?
이 현장의 진짜 드라마는 무엇인가?
무엇을 보여주면 문장군이 믿을 만해질까?
무엇을 버려야 30초 안에 살아날까?
```

이 질문에 답한 뒤에야 HTML을 만들 수 있다.
