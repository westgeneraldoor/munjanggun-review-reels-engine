# 릴스 게시 문안 표준 v2

캡션과 해시태그는 별도 파일이 아니라 최종 `*_script.md` 안의 `## 캡션`,
`## 해시태그` 절에 포함합니다. `caption.txt`, `hashtag.txt`, `hashtags.txt`는 만들지
않습니다.

## 1. 캡션

권장 길이는 6~9줄입니다. 정해진 문구를 복사하지 말고 해당 리뷰의 사건과 사진에
맞춰 씁니다.

필수 요소:

- 고객의 구체적인 문제 또는 상황
- 해당 리뷰에서 확인되는 디테일 2개 이상
- 해결 뒤 확인된 변화
- 원문을 과장하지 않는 신뢰 근거
- 자연스러운 상담 CTA 또는 저장할 이유

금지:

- 원문이나 중앙 증거에 없는 가격·기간·추가 비용·성능 수치
- `완벽`, `100%`, `무조건`, `보장`, `최저가`, `No.1` 같은 단정
- 모든 리뷰에 같은 감성 문구와 CTA를 붙이는 것
- 리뷰 수, A/S, 서비스 지역, 이벤트 등 변동 claim을 확인 없이 쓰는 것

변동 claim은 중앙 `EVIDENCE_REGISTER.md`를 확인하고, 접근할 수 없으면 문안에서
제외하거나 사용자 확인 대상으로 남깁니다.

## 2. 해시태그

20~25개를 권장합니다. 아래 세 태그는 항상 포함합니다.

- `#문장군`
- `#문장군중문`
- `#문장군시공`

나머지는 리뷰 근거에 맞춰 브랜드, 제품, 공간, 문제, 지역, 생활 변화 범주를
균형 있게 고릅니다. 실제 내용과 무관한 인기 태그, 경쟁사명, 반복·스팸 태그는
사용하지 않습니다. 외부 해시태그 bank는 아이디어 참고일 뿐 이 문서보다 높은
권위를 갖지 않습니다.

## 3. 최종 확인

1. 캡션의 모든 사실을 원문·사진·중앙 증거에서 찾을 수 있는가
2. 리뷰 고유 디테일이 2개 이상 있는가
3. CTA가 강요가 아니라 다음 행동을 설명하는가
4. 필수 해시태그 3개와 총 20~25개 범위를 지켰는가
5. 별도 caption/hashtag 파일을 만들지 않았는가

게시·성과 상태는 문안 파일이나 수기 대시보드로 추정하지 않습니다. 별도 명시
증거가 없으면 package state에서 `unknown`으로 유지합니다.
