## 3. 충돌 처리 기준

중앙 원본과 프로젝트 문서가 다르면 바로 덮어쓰지 않는다.

아래 순서로 판단한다.

1. 중앙 브랜드 전체에 해당하는 브랜드 정체성, 제품 범위, 현장 판단, 디자인 기준이면 중앙 원본을 우선한다.
2. 리뷰 릴스 제작, 원문 왜곡 방지, 사진/영상 privacy QA, TTS/HTML/MP4 승인 게이트처럼 채널 운영에만 필요한 규칙이면 프로젝트 어댑터를 우선한다.
3. 프로젝트 문서에 더 최신이거나 더 정확한 문장군 정보가 있으면 중앙 업데이트 후보로 기록한다.
4. 사실 여부가 불확실하거나 고객자료/통계 원본이 필요한 내용은 확인 필요로 남기고 발행 문구에 쓰지 않는다.

## 4. 중앙 원본 접근 실패 시 fallback

중앙 브랜드 폴더에 접근할 수 없으면 아래 순서로 fallback한다.

1. `docs/brand/PROJECT_BRAND_ADAPTER.md`의 요약 기준을 따른다.
2. 기존 루트 `BRAND_CONTEXT.md`는 legacy 참고로만 본다.
3. 중앙 원본과 충돌 가능성이 있는 숫자, 가격, 지역, 이벤트, 리뷰 수는 발행 문구에 확정적으로 쓰지 않는다.
4. 확인이 필요한 항목은 사용자에게 확인 요청하거나 `확인 필요`로 감사 문서에 남긴다.

## 5. 민감정보 금지

중앙 브랜드 폴더와 이 프로젝트의 GitHub 관리 문서에는 아래 정보를 넣지 않는다.

- 고객명
- 전화번호
- 상세 주소, 동/호수
- AppSheet 원본 레코드
- 상담 원문
- 네이버 관리자 통계 원본 XLSX/PNG
- 현장 사진 원본
- 리뷰 캡처 원본
- 비공개 매출, 계정, 토큰, 쿠키

필요한 경우에는 비식별 요약 또는 `evidence_ref`만 남긴다.

예:

```text
비식별 요약: 구축 아파트 현관 소음/냄새 불편을 리뷰에서 언급한 사례
evidence_ref: reviews/inbox_YYYYMMDD/033_*.txt
```

원문 리뷰, 고객 사진, 음성, MP4, HTML 출력물은 이 저장소의 GitHub 관리 대상이 아니며 로컬 산출물로만 관리한다.

## 6. 이 프로젝트의 브랜드 판단 원칙

문장군 리뷰 릴스는 중앙 브랜드 원본을 따라 아래 기준을 지킨다.

- 제품 설명보다 고객 문제와 사건을 먼저 보여준다.
- 무료 방문실측은 단순 견적이 아니라 선택 불안과 가격 불안을 낮추는 핵심 브랜드 경험으로 다룬다.
- 가격, 리뷰 수, A/S, 시공 가능 여부는 중앙 원본 기준으로만 표현한다.
- `완벽`, `100%`, `무조건`, `최저가`, `No.1` 같은 단정 표현은 쓰지 않는다.
- 실제 고객 리뷰에 없는 불편, 감정, 효과, 수치를 실제 사건처럼 만들지 않는다.
- 디자인은 실제 주거 공간 사진, 단단한 한글 타이포, 절제된 신뢰 포인트를 우선한다.
